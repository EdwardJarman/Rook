The installer I uploaded to the release has a **blank white window** when launched. The Tauri shell starts, the window appears with the title "Rook", but the React app never paints. Root cause: `AuthGate` called `useClerkAuth()` outside of a `ClerkProvider` when `VITE_CLERK_PUBLISHABLE_KEY` wasn't set in the build env, Clerk threw, React crashed during first render, and the Tauri webview silently swallowed the error.

**The fix is already written** (4 files in `C:\Users\marti\AppData\Local\Temp\rook-handoff\`):
- `auth-gate.tsx` — now owns the `ClerkProvider` boundary; without a key it shows a footer banner and lets the rest of the app run offline. 8s timeout for Clerk load with a "Sign-in unavailable" fallback.
- `error-boundary.tsx` — new `<ErrorBoundary>` wrapping the whole app; render errors show a dark themed panel with the stack trace and a Reload button.
- `App.tsx` — removed the old `ClerkProviderRook` wrapper (now lives inside `AuthGate`).
- `main.tsx` — added `window.error` and `unhandledrejection` listeners that `console.error` the cause.

These 4 files need to land on `main` and a fresh Tauri installer needs to be built and uploaded to the v0.2.0 release (replacing the broken one).

### 5. Fix the CI release workflow so the next tag actually produces installers

The two issues:
- **`pnpm install --frozen-lockfile` can abort at ~2 minutes** on the runners. Workaround that already shipped: switch to `pnpm install --prefer-offline` (commit `9514b8d`).
- **`pnpm bundle:js` was failing** because `src/uplink/uplink.ts` imported two helpers that didn't exist. Fixed in commit `a2fe897` (`buildDesktopPairingUrl` and `normalizeDesktopPairingCode` added to `src/shared/node-relay.ts`).
- **`tsc --noEmit` was failing on the api function** because it imports a build artifact. Fixed in commit `bc9073d` (`api` added to root `tsconfig.json` exclude).

So the CI *should* work now. The v0.2.0 tag needs to be **deleted and re-pushed** to trigger a fresh workflow run. Once the new Tauri commands (`pick_folder`, `list_dir`, `read_text_file`, `write_text_file`, `open_path`, `disconnect_node`, `add/remove/list_linked_root`) are in `src-tauri/src/main.rs` (they are), the `pnpm dlx @tauri-apps/cli@2 build` step will produce installers for Windows / macOS arm64 / macOS Intel / Linux.

### 6. (Optional but important) Fix the Tauri `externalBin` path

`rook-node/src-tauri/tauri.conf.json` says:
```json
"externalBin": ["binaries/rook-node-sidecar"]
```

Tauri 2 actually wants the file to be named `rook-node-sidecar-<rust-target-triple>` (e.g. `rook-node-sidecar-x86_64-pc-windows-msvc.exe`). The release workflow's `pnpm dlx @yao-pkg/pkg` step produces the file with that suffix, so it's correct — but if the CI ever builds without the pkg step, the build will fail. Add a sanity check or rename the field to match the actual file.

### 7. Long-term: connect git to Vercel

`https://vercel.com/rooks-projects/rook/settings/git` → Connect `EdwardJarman/Rook` → Production branch `main`. After that, every push auto-deploys and you don't need to run `pnpm vercel:deploy` manually.

## Architecture summary (what v0.2.0 *is*)

```
rook-node/
  index.html                       # Vite entry (title "Rook")
  vite.config.ts                   # @ → src/app alias, outDir: dist-app
  tsconfig.app.json                # strict, jsx: react-jsx, DOM lib
  src/
    index.ts                       # Sidecar CLI entrypoint (UNCHANGED)
    core/node.ts                   # Execution authority (UNCHANGED)
    gateway/server.ts              # Loopback gateway on 127.0.0.1:37831 (UNCHANGED)
    uplink/uplink.ts               # Cloud uplink (UNCHANGED)
    runtime/chromium.ts            # Pinned Chromium supervisor (UNCHANGED)
    control/, files/, screens/, security/, state/, supervisor/, registry/  # UNCHANGED
    shared/node-relay.ts           # ADDED buildDesktopPairingUrl + normalizeDesktopPairingCode
    app/                           # NEW — the Vite/React desktop window
      App.tsx                      # Providers: Theme + QueryClient + AuthGate + Router
      main.tsx                     # ReactDOM + ErrorBoundary + global error listeners
      router.tsx                   # Hash routes: /, /bots, /library, /files,
                                   #   /computer, /approvals, /account, /settings
      components/
        auth-gate.tsx              # Owns ClerkProvider; 8s load timeout
        error-boundary.tsx         # Renders errors instead of blank page
        shell.tsx                  # Sidebar + titlebar + status footer
        avatar.tsx, modal.tsx, primitives.tsx  # UI primitives
      routes/
        workroom.tsx               # Chat: bot strip, composer, messages, approvals panel
        bots.tsx, library.tsx, files.tsx,
        computer.tsx, approvals.tsx,
        account.tsx, settings.tsx, sign-in.tsx
      lib/
        trpc.ts                    # tRPC client (Vite stub router; talks to the live server)
        theme.tsx, theme-style.tsx, tokens.ts  # Canvas/Surface/Ink/Accent design tokens
        store.ts                   # tauri-plugin-store wrapper (localStorage fallback)
        node-bridge.ts             # window.__TAURI__.invoke wrappers
        workspaces.ts              # Linked-folder store (Codex/Claude-style)
        workroom.ts                # In-memory workroom model
        send-bridge.ts             # rook:send CustomEvent → tRPC mutation
        cn.ts, api-base.ts         # utilities
  src-tauri/                       # Tauri shell (Rust)
    src/main.rs                    # Existing + new commands:
                                   #   pick_folder, list_dir, read_text_file, write_text_file,
                                   #   open_path, disconnect_node, add/remove/list_linked_root,
                                   #   get_node_status
    tauri.conf.json                 # frontendDist: ../dist-app, identifier: com.rook.desktop
    capabilities/default.json      # + dialog/fs/store/opener/clipboard permissions
```

**Transport:** the Vite window authenticates with Clerk and calls tRPC over HTTPS to the same Vercel server the Expo web app uses. The Tauri shell still spawns the local sidecar for computer-use tasks. The `node-bridge.ts` module wraps `window.__TAURI__.invoke` calls (with loopback-gateway fallbacks for dev).

**Key invariant:** the sidecar (Node.js in `rook-node/src/`) is unchanged. Only the Tauri *window* changed — from the old 3-tab paired-node console to the full chat workroom.

## Things that are still rough

- **macOS / Linux installers** — the CI has been failing; needs the fixes in this handoff applied + the workflow re-triggered.
- **Auto-update** — `tauri-plugin-updater` is not yet wired. Phase 2 per the docs.
- **Code signing / notarization** — unsigned binaries; users get SmartScreen warnings on Windows and the `xattr` step on macOS.
- **The Tauri commands** (`pick_folder`, etc.) use a deny-by-default linked-roots scope with a 2 MB size cap. That's solid but the UI for managing the linked roots is the new `/files` page.
- **The `pnpm` postinstall** downloads Playwright Chromium (~500 MB). This is why the CI is slow on a fresh runner. Consider moving the Chromium into Tauri resources only.
